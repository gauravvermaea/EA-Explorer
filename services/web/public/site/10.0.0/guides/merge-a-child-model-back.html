Merge a child model back

For: Model Admin

A child's changes sent to its parent, reviewed change by change, and merged as one commit.

On this page
  • Why do this
  • The ways to do it
  • Each task, one page
  • Related

Why do this

Merging brings a working copy's changes back into the live model after review, so teams can work apart and still end up with one model. See Versions, tags and merging.

Nothing in EA Explorer is lost: every change is kept, moments can be named, and work can happen in copies that merge back after review. This is what lets many people change one model without fear.

In TOGAF terms: Phase H and the Architecture Repository: change to the baseline is controlled, recorded and reversible. See EA Explorer and the TOGAF Standard.

The goal: A child's agreed work is in the parent.

Before you start You need Model Admin on the child to send, and Model Admin or Committer on the parent to review.

The ways to do it

  1. On the child: Model Admin › Wizards, Send for merge into the parent. It shows what changed since its starting point; add a note and send.
  2. On the parent: Architecture Work › Merge requests, open the request. Where both changed the same thing, it is a conflict.
  3. Accept or reject each change (a reason for each rejection), then merge it as one commit. A merge report can be downloaded in Word.
  4. Then the child is frozen, or refreshed from the parent to carry on.
