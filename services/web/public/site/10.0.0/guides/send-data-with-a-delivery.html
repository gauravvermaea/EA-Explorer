Send data with a delivery

For: Developers

Your system writes the published Excel or CSV format; EA Explorer previews it for a Committer to accept.

On this page

Why do this

Deliveries are how other systems feed EA Explorer without direct access: a file in an agreed shape, reviewed before it counts. See Data in and out: integration.

Every route in ends the same way: what arrives is shown as new, changed, kept and problem rows, and a person decides. That review is what lets you automate feeds without losing control of the model.

In TOGAF terms: Supports the content of phases B, C and D (baseline architectures), keeping the Architecture Landscape current from the systems that already know it. See EA Explorer and the TOGAF Standard.

The goal: Another system's data reaches a model, reviewed.

Before you start The model's Model Admin has set up a delivery source for your system.

The ways to do it

  1. Get the empty template: the model's Import and export, choose the types, tick Empty template, Excel or CSV set. It has exactly the columns and drop-down values the model accepts.
  2. Write your data in it. Rows are matched by type and name: an existing entity of that type and name is updated, otherwise a new one is made. A delivery never deletes.
  3. Deliver it, one of three ways:
    • A folder: drop the files in the source's incoming folder, then Take dropped files (or eax import <source>).
    • The API, as the source's service account:
curl -H "Authorization: Bearer <token>" -F file=@cmdb.zip https://<your EA Explorer address>/api/v1/import-sources/<source id>/deliveries
  • An upload on the Deliveries tab.
  1. It waits for review: a Committer accepts or declines it.
