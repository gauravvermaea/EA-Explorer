Why a routine

Most faults show themselves in one of a few places. Looking in the same order each time finds them fastest.

The tools

ToolWhat it shows
.\eax debugStarts like up but does not stop on a failure, then records every container's output to work/logs/containers-<date-time>.log until Ctrl+C. .\eax debug api records the API and database only
.\eax clean-debugA clean start ending in debug mode
.\eax logs <service>One container's log
.\eax diagA diagnostics report: containers, health, recent errors
System Admin › Logs, Containers, HealthThe same in the screens
System Admin › Tools › SQLRead the database with your sign-in
/api/docsTry any API call with your sign-in
The browser's developer toolsThe screens' console and network calls; each API answer carries a request id that is in the API's log
.\eax test smoke and Self-test › WatchThe self-test as it runs, with screenshots and video of a failed browser journey

A routine that works

  1. Reproduce it, and note the time.
  2. Health and Containers: is a service down?
  3. The browser's network tab: which call failed, with which status and request id?
  4. The API's log at that time, by request id.
  5. Fix, then add a test that fails without the fix (Test it).
