Release 8 (built 19 to 21 Nov 2026; accepted and closed 21 Nov 2026, the owner: "accept release"): EA Explorer tests itself harder. One command runs every test, scans the code, attacks the installation and checks backup and restore; a summary page shows the result; and code coverage is measured and shown. For people using EA Explorer little changes: a Questions page on the website, and How do I under Documentation.

Before updating: take a backup (.\eax backup before-8.0.0). The update runs migrations 0110 to 0112 (the attack suite, the test summaries, the version). Then .\eax up (it rebuilds what changed and keeps your data) and .\eax test smoke. For the new Jenkins jobs: .\eax jenkins pipelines.

For everyone

  • Questions on the website (Questions in its menu, and ? › Questions or Documentation › How do I in EA Explorer): every How do I question once, with tabs by role and a search box. Each opens to its quick steps, the How do I page and the printed guide and chapter to read, and its video (coming soon).
  • Documentation starts with a How do I sub-menu: help for this page (F1), Questions, and the How do I pages by role. The ? menu is still there.
  • The AI (MCP) page's How do I links open the right page again (they went nowhere).
  • The website shows its version at the foot of every page, and inside EA Explorer its build too, as EA Explorer does.

Testing (for administrators)

  • **eax test full** from the command line now does everything but the performance test, one step after another: the dev check (lint, unit tests, documents), the self-test, the attack test, the backup and restore test and the SonarQube scan. **.\eax test summary** shows the last one.
  • The summary page: each full test writes one page with every step, the counts, the security findings, the memory used and the coverage (System admin › Self-test › Summary, and work/tests/full-<time>/index.html). The summaries are kept in the database; the detailed result files can be deleted from the screen or eax test prune, and the summaries stay.
  • Cleaning up (System admin › Command centre › Schedules, the regular maintenance): old logs and test result files deleted too.
  • The attack test (eax test attack, also in Jenkins › eax-admin › Upkeep): it tries to break EA Explorer, black box and white box, with each tool at its newest: an OWASP ZAP full scan, the API fuzzed with Schemathesis, Nuclei on every container's port, Semgrep and Gitleaks on the source, and forged and tampered sign-in tokens. In the first runs every attack was refused. A laptop only, unless allowed. Printed guide 26, Security and performance testing, describes it.
  • SonarQube (eax test sonar, and eax sonar open for its own pages): the whole repository scanned by SonarQube Community Build; 299 of the first 504 issues fixed with nothing changed for users.
  • Code coverage measured across the API, the job runners and the MCP server while the self-test runs, and shown as a ring on the test run and the summary page.
  • Test containers no longer stay running: each scan's container is removed when it ends, and any left by a run that stopped is removed at the next run's start and end, and by eax up. SonarQube and the other test containers never start in regular operation.
  • eax dev check works on a computer without the test tools (it runs in the test runner).

Fixed

  • eax screen no longer stops when its refresh lands while a menu is open.
  • The backup and restore test reads only its own window for jobs run twice, and says why a sign-in had no answer.
  • The dev check no longer ends with a coverage error when two measurers start at once.
  • System admin's resource history refuses ?days=nan; other findings of the attack test fixed (D823).
  • 21 security findings that are by design or false matches are accepted in writing until 21 May 2027 (D835).

Known, for Release 12

Certificate mode (eax init --certificate, the services signing in to the database with certificates) does not work in 8.0.0: the API cannot open its key and restarts. Use password mode (the default on a laptop). It is fixed in Release 15.

Coverage is 57.7% of our code, from the self-test alone; the goal is 90% (R12.5), with the final joined figure on screen (R12.15). The remaining SonarQube issues (R12.17); SonarQube after a clean restart (R12.10) and two scans at once (R12.16); 161 package updates in the images (R12.4); 4 report checks that fail on a host short of memory (R12.9); 3 unit tests (R12.8). Every open bug is listed in Release 12.
