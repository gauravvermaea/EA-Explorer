EA Explorer 3.0.0: Release 3

On this page

  • The eax command
  • Administration

Release 3 (14 Nov 2026): data discovery and ingestion (a reverse OData feed, pushes with a Python kit, documents read by AI, all reviewed as deliveries), Import and export guided step by step both ways, and testing that proves the whole product: negative tests for every endpoint, code coverage graphs, watching a run, the restore suite, the API harness, a security review with a Content-Security-Policy, and the eax screen.

Before updating: take a backup (.\eax backup before-3.0.0). From 2.0.0 the update runs migrations 0068 to 0072 (the restore suite, the API harness's cases, text indexes, discovery; indexes and tables only, nothing removed). Clean rebuilds now fetch current base images, so the first one takes longer. After it, run .\eax test full.

Known issues, fixed in Release 4 (from the last full self-test, R4.13 to R4.17): a body that is not JSON sent to a model's archive is acted on (it archives the model); three server errors where "not found" belongs; System Admin › Scaling fails when a container has just gone; the iteration journey's step 14; and some of the self-test's own checks.

Data discovery and ingestion

  • A reverse OData feed: Import and export › Discovery points a model at an OData feed EA Explorer reads, an endpoint other systems push to, or documents the AI engine reads. EA Explorer discovers the sets, fields and keys, suggests where each goes, and each run (now, daily or weekly) sends only what is new or changed as a delivery to preview and accept; names close to existing elements are suggested as matches to confirm. The AI engine is off until a Super Admin chooses one: cloud with your own key, or local (the Release 3 epic, D670; docs/discovery.md).
  • Push with Python: a push source's Discovery panel shows a short Python script to copy and downloads it as a kit (the script, requirements.txt, a README with the venv steps, sample CSVs from the model's metamodel): it reads CSV files and pushes them with push_dataframe(url, df, username, password), or a token, API key or client certificate (D674). Its samples are a file for every entity type of the model, each showing a relationship the metamodel allows, and the README lists how each relationship is published.
  • Import and export, step by step: Bring data in and Take data out guide you from "where is the data?" or "what is it for?" to the right screen and the review, whichever way the data comes or goes (D676).
  • Delete a discovery source (after a confirm; refused while a delivery of it waits; what it delivered stays, D675).

The eax command

  • **eax screen**: a full-screen eax in the style of Turbo Pascal, opened by plain eax: menus with Alt letters and the mouse, a dialog per command that shows the command as you fill it, a live dashboard of the containers and disks, and output in a window or the plain terminal; the numbered eax menu stays (R3.1, D669).

Administration

  • A full file explorer: a container's Files tab has File, Edit and View menus and a right-click menu, Details, List and Large icons views and a Preview pane, keys (F2, Delete, Ctrl+C / X / V / A and more), choosing several at once (one zip, cut, copy, move, delete), Properties, and drag and drop to upload or move; System Admin › Mounts opens a mount in the same explorer (R3.5, D668).
  • Users shows projects too: System Admin › Users › People lists each person's projects with their roles beside their models with their roles, as two plain lists; the CSV has a Projects column (R3.3).

Estate

  • Clean estate diagrams: System Admin › Estate draws every line at right angles around the boxes with an arrowhead and a label, keeps text inside its box, lists each host folder once (single files and finished one-shot containers apart), and keeps the logical columns level; the draw.io downloads keep the same routes (R3.4, D667).

Speed

  • Faster text searches: exact name lookups go through a hashed-name index, and Find, search and filters through trigram indexes on every column they look in (name, display id, description, merged-away names); migration 0070 (R3.7, D665).

Testing

  • GitHub's checks pass again: the API tests ran into "No module named 'eax'" on every push since 5 Nov 2026 (R3.15, D657).
  • Browser journeys on a busy machine: a step that looks in a row or a pop-up waits for it to appear; saving an iteration and sending a merge request are given longer; a failed step also says what an open dialog showed (R3.14, D658).
  • The full backup-and-restore test: eax test restore (and the end of eax test full from the command line) backs the installation up, changes it, restores it every way (all models, one model, and the infrastructure backup part by part) and checks all the content each time; a safety backup is put back if anything fails (R3.8, D659).
  • The upgrade test checks the way back: the updater's own backup is checked and eax rollback is run and checked; a runbook for upgrading 1.0.0 to 2.0.0 on a laptop and a server (R3.11, D660).
  • Far fewer skipped checks: the self-test finds the ids it needs from the lists it can read, checks the heavy reads in a bounded way, mounts persist/ in every runner and opens the break-glass page on its own (R3.13, D661).
  • API test harness (Self-test › API harness, and eax test api): pick any endpoint, call it as yourself or a test role, see the answer and the same call as a curl line; save calls as cases the self-test runs too (R3.16, D662).
  • Negative tests for every endpoint: the full self-test sends every write bad JSON and a list where an object belongs, every read an id that is not there, and long names inside its test data; a server error or a success fails the check. Code coverage under 90% is a warning; an area falling more than 2 points since the last run of the same kind fails (R3.9, in part, D663).
  • Coverage as graphs: a run's page shows a gauge against 90%, the areas least covered first, the trend over the last runs and the negative tests by kind; the same in the reports and a line in eax test (R3.10, D664).
  • Watch a test as it runs: Self-test › a run › Watch shows the step running and what it checks, each check as it is recorded, every failure with its reason, the counts and the log, with Stop; eax test watch and eax test stop do the same from a terminal (R3.2, D666).

Security

  • The whole release reviewed (docs/security-r3.md): discovery sources may sign in only with settings made for them and may not reach EA Explorer's own services, the machine or private networks unless IT allows a host; the screens' Content-Security-Policy is enforced; clean rebuilds fetch current base images so their fixes arrive; nginx 1.30 (R3.12, D671 to D673). Reports' remaining findings need Superset 6.1 (R4.7).
