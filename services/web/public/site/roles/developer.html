What EA Explorer has for developers

You bring data in and take it out: the REST API, the OData feed, the published import formats, deliveries, push sources with Python, webhooks and MCP.

On this page

Who this is for

People who connect EA Explorer to other systems: they write the scripts and ETL jobs that send data in, read models out for reports, receive EA Explorer's events, or build on its API. EA Explorer is not an ETL tool itself: it publishes its formats and feeds, and your jobs read and write them.

How it is put together

  • Signing in: a person signs in through Keycloak; a system uses a token or API key (sent as Authorization: Bearer ...) or a client certificate on the machine-access port. Each is limited to the areas and models you choose, expires, can be revoked, and every call is in the change log.
  • Data goes in as a delivery or a load: matched by entity type and name; a delivery only adds and changes (it never deletes), and keeps EA Explorer's values unless its source's values are set to win; nothing reaches the model until a Committer accepts it.
  • Data comes out through the OData feed (read only, with the reader's permissions), the REST API, Excel and CSV exports, and model packages.
  • IDs: every entity has a GUID and a display ID (for example APP-0012). Deliveries match by name, so your system does not need EA Explorer's IDs.
  • Permissions always apply: a token or a person reads only what they may read, and changes only what they may change.

How do I: your tasks

Bringing data in

  • Push data with PythonA push source and the Python kit: your records sent in one call, proposed as a delivery.
  • Send data with a deliveryYour system writes the published Excel or CSV format; EA Explorer previews it for a Committer to accept.
  • Set up a delivery sourceAnother system sends its data to a model as deliveries, each previewed and accepted by a Committer.

Taking data out

  • Read a model in Power BI or ExcelThe model's OData feed: every entity type as a table, read only, with your permissions.
  • Receive webhooksSigned messages to your system when something happens in EA Explorer.

Access for systems

  • Call the REST APIEverything the screens do, from a script, described with OpenAPI.
  • Get a token or an API keyA credential for a script or another system, limited to what it needs.

AI

  • Connect your AI assistantYour own AI app talks to EA Explorer through MCP, as you, with your permissions.
  • Discover the enterprise with AIYour AI assistant reads your sources and proposes what it finds for a model.
