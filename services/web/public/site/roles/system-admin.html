What EA Explorer has for System Admins

You run the installation: who may sign in and what they may do, security, backups, updates, health and the machine itself.

On this page
  • Who this is for

Who this is for

The people who run an EA Explorer installation. In EA Explorer these are the Super Admin (everything, including settings and the delete-everything commands) and the IT Admin (running it: health, backups, updates, containers, logs), helped by the User Admin (people and their roles) and the Auditor (sees everything a Super Admin sees, changes nothing).

What you have

Everything you need is under System Admin in the menu bar, and on the machine in one command, eax.

On the machine, eax starts, stops, backs up, restores, updates, tests and repairs EA Explorer, on Windows, Linux and macOS (.\eax in PowerShell, ./eax.sh elsewhere). eax help lists every command. Jenkins, if you start it (eax jenkins up), gives a pipeline for each command.

How it is put together

  • Containers: EA Explorer runs as a set of Docker containers on one machine (or several, when scaled out): the screens, the API and its jobs, the database (PostgreSQL), sign-in (Keycloak), reports (Apache Superset), documents (Mayan EDMS), the drawn views (draw.io), the operations helper, backups, and a front door that every request passes through. System Admin › Running › Estate draws them.
  • People and roles: people sign in through Keycloak, from its own accounts or your directory. Their global roles (Super Admin, IT Admin, User Admin, Auditor, Model Creator, Library Admin, Discovery Admin, Architecture Board, User) come from Keycloak; their model roles (Model Admin, Model Sub Admin, Committer, Architect, History Viewer, Report Viewer) and project roles (Project Admin, Lead Architect, Architect, Stakeholder and others) are given on each model's and project's People tab.
  • Where the data lives: one PostgreSQL holds the repository and its parts in schemas of their own; documents, reports and the drawn views keep their own databases. Each can be moved to a server of its own (System Admin › Running › Databases).
  • The config file: work/eaexplorer.env holds the settings the containers start with. Passwords and keys are separate files, one per container, never shown on screen (System Admin › Running › Secrets shows each by name, its age and when it is due).
  • Backups: an infrastructure backup holds every database, the files, the config and the versions; an application backup holds one model. Both can be tagged, pinned, checked and restored whole or in part.

How do I: your tasks

Getting around

  • Get help on any screenWhat the screen in front of you is for, and how to use it.

Taking data out

  • Receive webhooksSigned messages to your system when something happens in EA Explorer.

Access for systems

  • Get a token or an API keyA credential for a script or another system, limited to what it needs.

People and access

  • Add a person and give them rolesPeople sign in through Keycloak; their roles on the installation come from Keycloak, and their roles on each model and project are given there.
  • Map directory groups to rolesMake a Keycloak role or a directory group give an EA Explorer role, so people get their roles from the groups they are already in.

Security

  • Get an administrator back inA forgotten password, a locked account or a lost phone, sorted from the machine.
  • Limit who can reach EA ExplorerIP allow lists: only the addresses you list may reach EA Explorer, its sign-in pages, System Admin, the AI connector or the machine port.
  • Put in your organisation's certificateReplace the self-made certificate with your organisation's, so browsers trust EA Explorer without a warning.
  • Rotate passwords and keysChange EA Explorer's own passwords and keys, one at a time or all at once, now or on a schedule.
  • Turn on multi-factor sign-inAsk admins, or everyone, for a one-time code from an authenticator app when they sign in.

Backups and recovery

  • Restore a backupPut back a model, a project, part of the installation or all of it, from a backup.
  • Set up a DR siteA second EA Explorer kept up to date with this one, read only, ready to take over.
  • Take a backup and check itA backup of the whole installation now, and a check that it restores, without touching what is live.

Running it

  • Check the health and alertsSee whether every part of EA Explorer is up, what is wrong, and who is told.
  • Copy settings to another siteExport the admin settings to a file, and import them on another site, with every difference shown first.
  • Put up a bannerOne short message under the top bar for everyone, or for admins only, with optional start and end times.
  • Run the self-testCheck the installation works: the smoke test in a few minutes, or the full test.
  • Schedule a commandAn eax command that runs by itself: a nightly backup, a weekly check, or once at a time.
  • Update to a new releaseMove EA Explorer to a newer release, with a full backup first and a way back.

AI

  • Look after the installation with AIFor admins: ask about the installation's state, usage and housekeeping.
