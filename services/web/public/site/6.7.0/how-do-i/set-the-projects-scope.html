Set a project's scope

For: Project Admin, Practising architects

Breadth, depth, time and what is out of scope.

Why do this

Scope (breadth, depth, time, and what is out) is the first protection against a project that grows without end. It is agreed in the ADM's Architecture Vision. See The ADM: how architecture work is done.

A project carries one pass of the ADM from vision to sign-off. Each task here is one of the steps along that route, and the project keeps them together so the whole story can be read later.

In TOGAF terms: Phase A, Architecture Vision: scoping the architecture effort. See EA Explorer and the TOGAF Standard.

The goal: Everyone knows what the project covers and what it does not.

Before you start You need a role on the project (Architect or higher), unless a step says otherwise.

Steps

  1. Open the project, Charter, Scope.
  2. Describe the breadth, depth and time.
  3. Say what is out of scope; Save.
