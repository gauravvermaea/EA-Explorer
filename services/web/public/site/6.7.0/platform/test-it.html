Why so much testing

EA Explorer holds an organisation's record and runs unattended on many machines. A bug that reaches an installation is expensive to find and fix there. Tests catch it on your machine instead, and a test for every fix stops the same bug coming back.

The layers

LayerCommandWhat it checks
Before anything.\eax dev check (--quick, --web)Lint, the Python tests, the documents' cross-checks, the help is ASCII; --web builds the screens
Python testspytest in services/apiUnits and contracts, no database needed
Database checkstests/sql/phaseN_checks.sqlRun in a transaction that is rolled back
The self-test.\eax test smoke / fullThe running installation: every role signs in, every page opens, the journeys, security, backups

The rule

Every fix comes with a test that fails without the fix and passes with it. Write the test first, watch it fail, then fix.
