EA Explorer 5.1.0: Release 5.1, stabilisation

On this page
  • The job queue
  • Screens
  • Testing

  • Not in this release

Release 5.1, a stabilisation release (16 Nov 2026; the owner: "release this as a stabalization release before we do any more work"; "make it 5.1"): the bugs found running 5.0.0 on a laptop and in its full self-test, fixed, each with a test that fails without its fix (D599); the job queue made visible and safe to look after; nothing new beyond that.

Before updating: take a backup (.\eax backup before-5.1.0). From 5.0.0 the update runs migrations 0090 to 0092 (the self-test's Jobs suite, two indexes for the service desk, the version; constraints, indexes and a row only). A clean rebuild is needed: the API's start-up, the job runner, the screens and the test runner change (.\eax clean-restart). Then .\eax test full.

The job queue

  • A database connection was ended every five minutes: the idle-session clean-up ended every connection on the server, not only idle ones. This was behind sample data stuck part-way, projects missing and backups that hung (R5.36).
  • System Admin › Running › Jobs: what is being worked on and what waits, in words; Kill, Cancel, Move up and down; the stuck ones counted on the dashboard with what to do, and an alert. Nothing is killed without a person saying so (R5.30). The same from the command line: eax jobs (R5.35).
  • Job slots set on screen, on Scaling and Containers, with a warning past the machine's CPU threads (R5.33); the job history deleted on screen (R5.34).
  • Each scheduled job runs one copy at a time (R5.30, R5.32); the industry packs load for at most 8 minutes a run and carry on at the next (R5.32), and their lock is never ended by database maintenance (R5.38).
  • Jobs left by a job runner that stopped are marked stopped when it starts again, so they no longer show as being worked on and their next runs start; each of the three job runners is watched (R5.45, R5.46).
  • Kill, Cancel, Move and Delete history work (they failed on the job runner's own database rules); Kill asks a running job to stop, and a second Kill marks one no runner has any more as stopped (R5.45, R5.46).
  • Waiting jobs say why: behind the earlier run of the same job, or put off to a later time, instead of "stuck" (R5.46).
  • The library models move once: the start-up step and the scheduled job no longer move them at the same time (R5.43).

Screens

  • A service request shows the project and the model by name, not by identifier (R5.37).
  • Operations and Personal data no longer flicker to "starting" when the API is busy (R5.39).
  • A value a caller gets wrong (not an identifier, not a date, not JSON) is answered "not valid" (400), never a server error (R5.40).
  • System Admin › Logs: the containers in a drop-down with a tick each, the time window labelled, and step-by-step help (R5.42).
  • The versions on the start-up status: the API, its database and the code on this machine; down when the API and the database differ, a warning when the code is newer than what runs (rebuild before testing); the self-test checks the running version and says when its runner was built from other code (R5.48).
  • System Admin › SQL: names only in the tree, with a Properties panel for the database, schema, table or view chosen (R5.44).

Testing

  • A Jobs suite in the self-test and the full test (eax test jobs): the job runner takes jobs, the alert checks run, nothing stuck, every scheduled job has its lock, Cancel, Move and Kill work on probe jobs rolled back (R5.46).
  • Each area's passed and failed on the self-test's area cards, while a run goes on and for a finished run (R5.47).
  • How many checks have run and are left in each phase, big on screen (R5.5.3).
  • The full test no longer backs up and restores the infrastructure (eax test backup-restore does), and never runs the performance test (R5.29, R5.31).
  • Fixed in the tests themselves (EA Explorer was not failing): the Reports suite read only the first 100 dashboards and counted chart requests aborted by moving to the next dashboard; the cross-model attack used addresses that had changed (R5.47).

Installing and starting

  • .\eax clean-restart no longer stops when Windows cannot start docker for one look ("The paging file is too small"): it says so and waits on (R5.41).

Not in this release

Everything recorded for later stays there: Release 5.5 (enterprise discovery, decision records), Release 5.6 (pausing a test, job priorities and fair turns, every job reviewed, Updates and Deploy from GitHub Releases), Release 6.6 (setup guides, database checks, an external database server, real certificates) and Release 5.7 (customer journey maps).
