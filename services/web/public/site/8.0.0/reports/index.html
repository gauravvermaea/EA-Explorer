Reports

Every standard report and dashboard: what it shows, who it is for, how to use it and how to read it, and where it sits in TOGAF. Open them on any model's Reports tab.

Data quality

  • QR-01 Data quality across modelsEach model's quality score and its parts (completeness, rules passed, freshness), and how they moved over time.
  • QR-02 Completeness by type and ownerCompleteness, failing rules, stale entities and orphans by entity type and by owner, weakest first.
  • QR-03 What to fixEvery finding of the latest measurement: missing values, failing rules, stale entities, orphans and broken seals, with who is responsible; each opens the entity to fix it.
  • QR-04 Failing rulesThe rules entities fail, errors first, and the entities failing each.

Dependency

  • DR-01 Dependencies of an entityChoose an entity: what it depends on (upstream) and what depends on it (downstream), up to six steps, with the path.
  • DR-02 Dependency matrix between two typesChoose the row type and the column type: every relationship between their entities.
  • DR-03 Impact chain from technology to value streamEach technology, the applications it serves, the processes and capabilities they support and the value streams those enable, with end-of-life risk.
  • DR-04 Dependency counts and hot spotsHow many entities each entity depends on and how many depend on it, banded by thresholds you choose.

Gap analysis

  • GR-01 Gap analysesEvery gap analysis: its template, baseline and target (models or tags), when compared, and how many gaps are open.
  • GR-02 Gaps by domain and typeKept, changed, new and eliminated elements by domain and entity type, for one or several gap analyses.
  • GR-03 TOGAF gap matrixThe TOGAF gap matrix: baseline elements down, target elements across; included, new and eliminated cells.
  • GR-04 Gap resolutions and work packagesHow each gap is closed (build, buy, retire, replace...) and the work packages that close it; the gaps still undecided.
  • GR-05 Gap entities in the modelsThe gaps added to the models as Gap entities, with the analysis, baseline and target they come from.

KPI trends

  • KR-01 KPI trendsEach model's KPIs over time: entities by type, applications by TIME and lifecycle, total cost, quality score, orphans, end-of-life technology and the model's own KPIs, kept on the 1st of each month and on every tag.

  • MO Model overviewHow many entities of each type, the models and recent changes (MOD-010).
  • SR-01 Application portfolio inventoryEvery application with owner, lifecycle, criticality, cost, vendor, hosting and TIME.
  • SR-02 Business capability catalogueThe capability hierarchy with levels, owners, maturity and how many applications support each.
  • SR-03 Technology component inventoryTechnology components with version, vendor, lifecycle and end of life.
  • SR-04 Data entity catalogueBusiness objects and data objects with owners and classification.
  • SR-05 Business process catalogueProcesses and functions by level with owners and the roles that perform them.
  • SR-06 Interface and integration catalogueFlows and other links between applications and interfaces, source to target.
  • SR-07 Stakeholder and actor catalogueActors, roles, collaborations and stakeholders.
  • SR-08 Motivation catalogueDrivers, goals, outcomes, principles, requirements, constraints and assessments.
  • SR-09 Application against capabilityWhich applications support which capabilities.
  • SR-10 Application against processWhich applications serve which processes.
  • SR-11 Application against data entity (CRUD)Which applications create, read, update or delete which data (the access type in each cell).
  • SR-12 Application against technologyWhich technology each application runs on.
  • SR-13 Process against roleWhich actors and roles perform or own which processes.
  • SR-14 Capability against value streamWhich capabilities enable which value stream stages.
  • SR-15 Application interaction matrixApplication-to-application flows.
  • SR-16 Capability heatmapCapabilities coloured by the number of applications supporting them, by maturity and by criticality.
  • SR-17 Technology lifecycle and end of lifeTechnology by lifecycle phase and end-of-life year, and what is past or near its end of life.
  • SR-18 Application TIME quadrantApplications by functional and technical fit (Tolerate, Invest, Migrate, Eliminate), with the TIME set on each.
  • SR-19 Criticality against technical healthBusiness criticality against technical fit for every application.
  • SR-20 Cost by capabilityApplication and technology annual cost rolled up to the capabilities they support.
  • SR-21 Vendor concentrationApplications and technology per vendor, with their cost.
  • SR-22 Impact analysisEverything that depends on a chosen entity, up to four steps away, with the path.
  • SR-23 Obsolescence riskApplications and capabilities at risk from technology past, near or phasing out of its end of life.
  • SR-24 Single points of failureApplications and technology ranked by dependants, and how many of them have no alternative.
  • SR-25 Rationalisation candidatesCapabilities served by more than one application, and the applications that overlap.
  • SR-26 Completeness by type and ownerHow complete each type and owner is, and the entities missing required values.
  • SR-27 Orphans and missing relationshipsEntities with no relationships, no parent and no children.
  • SR-28 Duplicate candidatesEntities of the same type with the same or similar names, with a similarity score.
  • SR-29 Change activityChanges by week, model, person and kind over the last two years.
  • SR-30 Comparison with the source modelEach model against the model it was created from: kept, changed, new and removed entities (gap analysis).
