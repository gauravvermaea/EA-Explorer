Who this is for

The people who run an EA Explorer installation. In EA Explorer these are the Super Admin (everything, including settings and the delete-everything commands) and the IT Admin (running it: health, backups, updates, containers, logs), helped by the User Admin (people and their roles) and the Auditor (sees everything a Super Admin sees, changes nothing).

A day in your life

Your morning starts with the dot in the top bar: green means the night's backups ran, the checks passed and nobody was locked out. Most days the work is small and steady: a new team needs access, a directory group should give a role, an alert about disk space wants a look, a release is waiting to be scheduled for the weekend. Some days are bigger: a restore drill, rotating every password before an audit, setting up a DR site, or getting an administrator back in when sign-in itself is the problem.

Where EA Explorer fits

EA Explorer is the platform your architects depend on, and you are the one who keeps it dependable. It is built to need little from you: it watches itself, backs itself up and checks the backups, tells you before anything risky, and writes every set-up down with your own values in the commands. Your job is to decide, not to fight the tool: who gets in, how safe it is, when it changes, and how fast it comes back if something goes wrong. See Running the installation and Roles and access.

Where you sit in TOGAF

The TOGAF Standard is about the architecture, not the tool that holds it, so most of your work sits outside the method. It serves the method all the same: the Architecture Repository the standard describes only helps if it is available, secure, backed up and current, and that is your part. See EA Explorer and the TOGAF Standard.

On the machine, eax starts, stops, backs up, restores, updates, tests and repairs EA Explorer, on Windows, Linux and macOS (.\eax in PowerShell, ./eax.sh elsewhere). eax help lists every command. Jenkins, if you start it (eax jenkins up), gives a pipeline for each command.

How it is put together

  • Containers: EA Explorer runs as a set of Docker containers on one machine (or several, when scaled out): the screens, the API and its jobs, the database (PostgreSQL), sign-in (Keycloak), reports (Apache Superset), documents (Mayan EDMS), the drawn views (draw.io), the operations helper, backups, and a front door that every request passes through. System Admin › Running › Estate draws them.
  • People and roles: people sign in through Keycloak, from its own accounts or your directory. Their global roles (Super Admin, IT Admin, User Admin, Auditor, Model Creator, Library Admin, Discovery Admin, Architecture Board, User) come from Keycloak; their model roles (Model Admin, Model Sub Admin, Committer, Architect, History Viewer, Report Viewer) and project roles (Project Admin, Lead Architect, Architect, Stakeholder and others) are given on each model's and project's People tab.
  • Where the data lives: one PostgreSQL holds the repository and its parts in schemas of their own; documents, reports and the drawn views keep their own databases. Each can be moved to a server of its own (System Admin › Running › Databases).
  • The config file: work/eaexplorer.env holds the settings the containers start with. Passwords and keys are separate files, one per container, never shown on screen (System Admin › Running › Secrets shows each by name, its age and when it is due).
  • Backups: an infrastructure backup holds every database, the files, the config and the versions; an application backup holds one model. Both can be tagged, pinned, checked and restored whole or in part.
