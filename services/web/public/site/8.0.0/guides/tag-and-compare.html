Tag a model and compare

For: Model Admin, Practising architects

A named moment of a model to go back to, and what changed since.

Why do this

Tags and comparison are how architecture shows change: baseline against target, before against after. See Versions, tags and merging.

Nothing in EA Explorer is lost: every change is kept, moments can be named, and work can happen in copies that merge back after review. This is what lets many people change one model without fear.

In TOGAF terms: Phase H and the Architecture Repository: change to the baseline is controlled, recorded and reversible. See EA Explorer and the TOGAF Standard.

The goal: You can name moments, compare them and go back.

Before you start Tagging needs Model Admin on the model; comparing needs a role on both models.

The ways to do it

  1. Tag it: Model Admin › Wizards, Tag it now, with a name (for example Baseline 2026). Every wizard that changes a model tags it first.
  2. Compare: Architecture Work › Compare and analyse › Compare models: two models, or one model at two tags. It shows what was added, changed and removed.
  3. Gap analysis: the same menu, Gap analysis, between a baseline and a target, with resolutions and work packages.
  4. Go back: the model's Tags tab, Restore a tag makes it the latest again.
