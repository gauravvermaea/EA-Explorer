Data in and out: integration

For: Developers, Model Admin, Practising architects

The ways data reaches EA Explorer from other systems and leaves it for them, and why everything is reviewed first.

On this page
  • Why integrate
  • Ways in
  • Ways out
  • Read next

Why integrate

Much of what the architecture needs is already known elsewhere: the application list in a service management tool, the servers in a configuration database, the teams in HR. Typing it in again is slow and goes stale. Integration brings it in on a schedule, and sends the architecture back out to the tools people already use for reporting.

Ways in

  • Excel: download a sheet with the model's own columns and drop-downs, fill it, load it (Load data from Excel).
  • Deliveries: another system drops a file in a folder; it waits as a delivery for a person to review (Send data with a delivery, Set up a delivery source).
  • Python or the API: a script pushes the data (Push data with Python, Call the REST API).
  • OData feeds: EA Explorer reads a feed your organisation already has (Read an OData feed from another system).
  • AI discovery: your AI assistant reads documents and proposes what it finds (Discover the enterprise with AI).

Whatever the way, what arrives is reviewed before it counts: new, changed and problem rows are shown, and a Committer accepts or declines. That review is what keeps automated data from quietly corrupting the model.

Ways out

Excel and CSV files, a whole-model package, OData for Power BI and Excel, the REST API and webhooks (Take data out with the guide, Receive webhooks).
