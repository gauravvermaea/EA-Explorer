Kinds of architecture project and their goals

For: Project Admin, Executives, Practising architects

The project templates EA Explorer offers, what each sets out to achieve, and how to choose one.

Why projects come in kinds

Architecture work is always done for a reason, and the reason decides the work. Documenting how things are today needs catalogues and diagrams but no target; a cloud migration needs a target, waves and a roadmap; a merger needs two current states side by side. A project template sets a project up for its reason: which ADM phases and steps it runs, which deliverables it produces, which models it needs and who signs off. You can change everything afterwards; the template is a good start, not a cage. See Start a project from a template.

The kinds and their goals

KindThe goal
TransformationMove from today's architecture to a target through intermediate states, with the gaps and a migration roadmap
Document the as-isA trustworthy picture of how the enterprise works today; no target
Create a new productDesign a new product or service: business model, value, capabilities and the architecture to deliver it
Copy a model for new reportsNew views and reports on a copy, leaving the original untouched
Copy, update and merge backUpdate a model's content in a working copy and merge it back when agreed
Scenario planningCompare two or more possible futures from the same starting point, before choosing
Regulatory or compliance changeTurn a regulation's obligations into requirements, find the gaps against controls, prove compliance
Technology refresh or cloud migrationMove technology to new platforms in planned waves
Application rationalisationDecide for each application: keep, invest, migrate or retire
Operating model redesignRedesign organisation, roles, processes and capabilities together
Capability-based planningPlan change by capability: current and target maturity, the gaps, the roadmap
Architecture assessment or health checkJudge existing models for quality, principles and risk; change nothing
Solution architecture for one initiativeThe architecture of one solution inside the enterprise picture, merged back after go-live
Due diligence, merger or acquisitionTwo current states, their overlaps, and a combined target

Choosing

Start from the question the sponsor needs answered. If nothing changes, it is documentation or an assessment. If one future is already chosen, it is a transformation, migration or solution architecture. If the future is still open, it is scenario planning. If an outside rule drives it, it is a compliance change. When in doubt, a blank project and the ADM phases you need are always possible (Start a blank project).
