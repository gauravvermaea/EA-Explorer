EA Explorer 14.0.0: Release 14, stabilisation

Release 14 (built 21 to 25 Nov 2026; accepted 25 Nov 2026, the owner: "Close it", "I think only reports is the issue"): every bug the full test found fixed, and the full test itself made something you can start and trust to finish. After a clean restart the dev check, the self-test, backup and restore, SonarQube and the DR drill all pass, except one check: every report opens (see Known issues).

Before updating: take a backup (.\eax backup before-14.0.0). The update runs migrations 0122 (five indexes on project tables) and 0123 (the version only). The api, web, ops and test runner images change: .\eax down then .\eax up is enough (no data is changed), then .\eax test smoke. Refresh the browser (Ctrl+F5).

What the last full test showed

  • Self-test: 3,101 checks passed, 3 failed, then 2 of the 3 passed when run again (the third is the reports check).
  • Dev check: 2,646 unit tests passed, none failed.
  • Backup and restore: passed: two backups, two full restores of the same backup, nothing lost (451 tables and 6,771 files compared).
  • DR drill: passed, 9 minutes from shutting the installation down to the DR copy restored and signed in to; every model, element, relationship, project, document and person counted the same before and after.
  • Security gate: no failing finding. SonarQube: nothing to fix.
  • Code coverage: 65.2% (the unit tests and the live run joined); the 90% bar is Release 14.5.

For everyone

  • Every list of models opens again: a name defined twice in the server code made every models list answer with an error; a test now refuses a name defined twice.
  • The start page's System admin tile is greyed, with the reason, for anyone the menu does not offer System Admin to (it was open to a Report Viewer).
  • The Documentation pages show their heading while the list loads.
  • Documents' text recognition (OCR) is off unless chosen, on its own Documents tab, any time or only between two times you set.

For system administrators

  • The web server runs nginx 1.30.7 (Alpine's), with the security fixes its makers' image does not carry yet.
  • The images take Alpine's newest package fixes at every build, not only when the base image changes.
  • Every container at a fixed version tag.
  • **eax diag writes its whole report; eax test sonar** runs one scan at a time; four Jenkins pipelines that could never run now ask for confirmation and run.
  • Before a full test the command says when Docker has too little memory (12 GB is needed).
  • Mail to an SMTP server over TLS checks the server's certificate and name.
  • Web addresses are opened over http and https only.
  • Containers' logs can be searched over the whole log, not only the last 5,000 lines.

Testing

  • The full test can be started and trusted to finish: the unit tests run on a copy of the code; a browser page that crashes fails only its own check; every step writes a summary even when one fails; SonarQube's findings are on the test report.
  • A failed browser step says what the open pop-up answered, so a failure can be understood from the report.
  • Journeys tick exactly the choice they name (a gate on phase B was never set: the RACI field's label held a "b").
  • Time limits that a busy laptop could not meet were raised (the AI tools 10 minutes a call, a report page 5 minutes).

Accepted in writing

  • 171 SonarQube findings (each with its reason) and the security findings with no fix released yet.
  • Two findings inside Docker's own command-line plug-ins in the ops image, until 31 Dec 2026 (no Docker release has the fix yet).

Known issues

  • Every report opens fails on a laptop: a report dashboard can take more than 5 minutes to open while the test runs, and ten take 31 to 91 seconds. Fixed in Release 14.5 (R14.5.19): the reports' queries made fast, the test made lighter.
  • Before Release 22, do not run clean-restart, clean-run or cleanup --all on a server: they delete every database without asking. Use .\eax up or .\eax restart, which keep the data. Keep scheduled backups on and copied off the machine.

Next

Release 14.5 (code coverage over 90%, journeys for every screen, then the reports made fast), then Release 22 (upgrading a running installation: eax update --from, the upgrade test in every release, nothing wipes production).
