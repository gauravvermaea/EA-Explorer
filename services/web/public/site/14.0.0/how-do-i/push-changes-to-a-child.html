Push changes to a child

For: Model Admin

Copy changes from a model down to one of its children.

Why do this

When the parent improves (a corrected capability map, a new attribute), pushing the changes to a child keeps it in step; the child's admins accept them. See Versions, tags and merging.

Nothing in EA Explorer is lost: every change is kept, moments can be named, and work can happen in copies that merge back after review. This is what lets many people change one model without fear.

In TOGAF terms: Phase H and the Architecture Repository: change to the baseline is controlled, recorded and reversible. See EA Explorer and the TOGAF Standard.

The goal: A child model gets its parent's newer changes.

Before you start You need the Model Admin role on the model.

Steps

  1. Open Model Admin › Wizards, Propagate to a child.
  2. Pick the child and what to copy.
  3. The child's admins accept them.
