AU-application_architect Application architect dashboard

For: Practising architects

The headline view of every report a application architect usually wants, on one page.

What it shows

What it gathers: SR-01 Application portfolio inventory, SR-09 Application against capability, SR-12 Application against technology, VP-02 Application Structure view, VP-08 Application Usage view, VP-09 Technology Usage view, VP-11 Application Cooperation view, TM-04 Application and organisation matrix, DR-02 Dependency matrix between two types, GR-02 Gaps by domain and type.

Why it matters

An audience dashboard gathers, on one page, the headline charts of the reports one kind of person usually needs, so they start from what matters to them instead of browsing the whole catalogue.

In TOGAF terms: Stakeholder management: each audience sees the views that address its concerns. See EA Explorer and the TOGAF Standard.

Who it is for

Application architect.

How to use it

Use it as the starting dashboard for the Application architect dashboard: the reports that matter to this audience, together.

How to read it

Each chart is described where it comes from; open the full report from the Reports tab for detail.

Where to find it

Open a model, Reports › Reports, and choose Application architect dashboard; it opens its dashboard for that model. Every chart can be filtered, and most rows have Open to go to the entity in EA Explorer. The same data is in the model's OData feed for your own tools (OData feeds EA Explorer publishes).
