Map a project's stakeholders

For: Project Admin, Practising architects

Who has power and interest, and how to engage each.

Why do this

Stakeholders differ in power and interest. Mapping them shows whom to manage closely, keep satisfied, keep informed or simply monitor, which shapes the project's communication. See Stakeholders and key questions.

A project carries one pass of the ADM from vision to sign-off. Each task here is one of the steps along that route, and the project keeps them together so the whole story can be read later.

In TOGAF terms: Phase A, Architecture Vision: stakeholder management. See EA Explorer and the TOGAF Standard.

The goal: You know how to engage each stakeholder.

Before you start You need a role on the project (Architect or higher), unless a step says otherwise.

Steps

  1. Open the project, Stakeholders.
  2. Set each stakeholder's power and interest.
  3. Read the map; plan how to engage each group.
