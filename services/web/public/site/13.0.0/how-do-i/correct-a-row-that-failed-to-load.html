Correct a row that failed to load

For: Practising architects, Developers

Fix one problem row of a load or delivery and check it again.

Why do this

When a load or delivery has problem rows, the rest can still go in; the problems wait. Correcting a row on screen and checking it again saves sending the whole file again. See Data in and out: integration.

Every route in ends the same way: what arrives is shown as new, changed, kept and problem rows, and a person decides. That review is what lets you automate feeds without losing control of the model.

In TOGAF terms: Supports the content of phases B, C and D (baseline architectures), keeping the Architecture Landscape current from the systems that already know it. See EA Explorer and the TOGAF Standard.

The goal: A rejected row is fixed and loads.

Before you start You need a role on the model that may change content (Architect or higher).

Steps

  1. Open the load or delivery; its problem rows.
  2. Correct a row: fix the value; Save and check again.
