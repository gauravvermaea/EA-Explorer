EA Explorer 13.0.0: Release 13, System Admin regrouped and every command-line option documented

On this page
  • For system administrators
  • The command line
  • Testing
  • Known issues
  • In one paragraph (for the GitHub release)

Release 13 (built 23 Nov 2026; accepted 23 Nov 2026, the owner: "ok this release is accepted", "lets close R13"): System Admin is easier to find your way around, in the menu and on the page, and every option of every command is written down, with a test that keeps it so.

Before updating: take a backup (.\eax backup before-13.0.0). The update runs migration 0121 (the version only). The web, API and test runner images change: .\eax down then .\eax up is enough (no data changes), then .\eax test smoke. Refresh the browser (Ctrl+F5) to load the new screens.

For system administrators

  • System Admin in seven groups, by what you are doing: Settings, People and access, Health and monitoring, Infrastructure, Capacity, Backups and recovery, and Tools, at most eight pages each (before: 37 tabs in one strip on every page, and 19 menu entries under Running).
  • Multi-level tabs, as Projects and models have them: every group as the first row of tabs, the group's pages as the second, and a page's own tabs as the third, with a line saying where you are. Each group opens on the page you last used in it, and each page on the tab you last used on it.
  • The same structure in the menu: System Admin › group › page › sub-page. A page's own tabs (Self-test, Command centre, Machine access, Containers, Users and roles, Estate) are now in the menu, and each has an address of its own (for example #/admin/self-test/summary), so links, bookmarks and the back button work.
  • One name for one thing: the tabs use the menu's names (Users and roles, Data quality, Secrets: passwords, keys and certificates, Branding: logo and themes, Site pairings: sync and DR sync).
  • Every old address still opens its page; who sees what in the menu is unchanged.

The command line

  • Every option documented: 25 of eax's own options that no help named are now in eax help under their command (among them eax test --role, --suite, --last, --report, --fixtures; eax logs backup --outside-work and --then-clear; eax help --groups and --search; eax restore-model --new and --over).
  • The DR tools have help: dr/eax-dr and dr/eax-drill (shell and PowerShell) answer --help (-Help in PowerShell) with every option; a missing folder or an unknown option shows the help and stops, instead of asking.

Testing

  • A unit test fails eax dev check when the code reads an option no help names; the Command centre's and Jenkins' fields must be in their command's help; the DR tools' two forms must take and describe the same options.
  • A browser journey (full test) walks System Admin's three levels: the groups, a group's pages, a sub-tab's address, back to where you were, and an old address. The smoke test opens every page and sub-page in the menu.

Known issues

  • Release 12's known issues stand (releases/12.0.0.md), all in Release 14 (R14.27 to R14.33).
  • On the Containers page the same "operations helper is not reachable" problem shows three times while EA Explorer starts (R14.35).
  • The guides and How do I pages do not describe the new System Admin layout yet: they are written with every other guide in Release 16.

In one paragraph (for the GitHub release)

EA Explorer 13.0.0 regroups System Admin into seven groups by what you are doing, with multi-level tabs like Projects and models (every group, the group's pages, a page's own tabs) and the same structure in the menu; every page and tab has its own address and you land where you last were. Every command-line option is now documented, the DR tools have --help, and a test keeps both true. Take a backup, then .\eax down and .\eax up.
