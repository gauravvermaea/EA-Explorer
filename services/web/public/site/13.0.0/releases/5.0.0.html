EA Explorer 5.0.0: Release 5

On this page
  • Security
  • Operations
  • Testing
  • For developers
  • Fixed while testing

Release 5 (released 15 Nov 2026; D696: built whole, tested with the automation, its bugs fixed, then released, nothing carried forward): running EA Explorer on a server with confidence: security at the front door, alerts, logs, database maintenance, an optimisation report, a service desk, and testing that runs by itself.

Before updating: take a backup (.\eax backup before-5.0.0). From 4.0.0 the update runs migrations 0078 to 0089 (machine credentials' addresses, the Auditor role, alerts, database maintenance runs, the service desk and its rework, the optimisation reports, the performance suite, sizing estimates, the live browser, a duplicate index removed, the version; tables and data only). A clean rebuild is needed: the operations helper, the front door's configuration, the set-up and the test runner change (.\eax clean-restart). Then .\eax test full.

Security

  • IP allow lists at the front door, per place (the screens, sign-in, administration, MCP, machine access), never locking out the person who sets them; a machine credential limited to its own addresses (R5.2, D686; eax allow).
  • Multi-factor sign-in as a setting, off by default: for admins or everyone (R5.3, D690).
  • The Auditor role (eax-audit): sees everything a Super Admin sees, changes nothing, never sees a secret (R5.22, D693).
  • Signed deployments, for an organisation that wants them: eax sign and eax verify; an update refuses a version not signed by a trusted key once one is trusted (R5.10, D685).
  • Automated security testing: weekly by itself and nightly in CI; a signed-in ZAP scan; code, secrets and licence scanning; the attacks of Release 3 kept as tests; a gate on high and critical findings with accepted ones that expire; the trend on Self-test › Security and an alert on a new finding (R5.17, D698).

Operations

  • Alerts: checks with levels, hold, flapping, acknowledge, silence, escalation, email and webhooks (R5.9, D689).
  • Logs: levels, every container's logs kept and rolled, the web log of every call, on System Admin › Logs (R5.6 to R5.8, D688).
  • Log files roll at a size set on System Admin › Logs (Size and keeping): 100 KB by default for every log file, and for Docker's own copy of each container's output from the next .\eax up; kept 7 days, however many files (R5.26, D701).
  • Database maintenance: every database checked daily, tidied nightly without locks, compacting and lock resolution after a preview (R5.12, D691; eax db).
  • The optimisation report: monthly suggestions with their evidence and the people who made and look after each model or project, applied only with a yes, for a whole model or project; on screen and as Excel (R5.1, D697; eax optimise).
  • Server sizing: a best estimate of RAM, CPU and disk, per container too, with a compose override (R5.19; eax estimate).
  • Where the data lives: one base folder, a folder per kind of data (R5.4, D687; eax folders).
  • The service desk: choose a group, then what you need (or "Something else"); every request goes to the Super Admins, who assign it to a person (R5.11, R5.27, D692, D700; eax ticket).
  • The version review every three months, as a scheduled task (R5.21, D694).

Testing

  • Performance testing: eax test performance, k6 with many people at once, compared with the last release's baseline; run only when asked for, never as part of the full test (R5.18, D695, R5.29).
  • Watch the tests' browsers live, streamed only while watched; slow motion and pause after each step; every journey's video and trace kept for a watched run (R5.20; eax test watch --browser).

For developers

  • Every module, class and function documented, kept so by a test; docs/functional-description.md (R5.14, R5.15).
  • docs/handover.md and eax dev check for whoever takes the work over (R5.16).

Fixed while testing

  • The clean rebuild stopped at the Reports image: it asked for an image library (Pillow 13) that Superset 6.1.0 cannot run. Superset's own version is kept; its findings are accepted until the version review on 1 Feb 2027, because the features that use it are off (R5.23, D699).
  • After the clean rebuild the site could not be reached: one line of the front door's configuration (the web log's day) was written in a way nginx refuses, so it never started (R5.24).
  • Multi-factor sign-in turned off still asked for a code from people who had set one up when it was on: turning it off now also removes the codes EA Explorer asked people to set up (R5.25).
  • Database maintenance found the background tasks' index made twice: the extra one is removed (R5.28).
