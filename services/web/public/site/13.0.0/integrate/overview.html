Why integrate

An architecture repository is only as current as its sources. The facts it needs (applications, servers, teams, contracts, costs) already live in other systems: a configuration database, a service management tool, HR, finance. A good integration brings them in on a schedule so architects work on judgement rather than retyping, and takes the architecture back out to the reports and tools where decisions are made. See Data in and out: integration.

The principle: EA Explorer publishes, you connect

EA Explorer is not an ETL tool and does not ship vendor-specific connectors. Instead it publishes stable formats and interfaces, and a connector is whatever reads your source and writes one of them. That keeps EA Explorer simple and lets you use the tools you already have: a Python script, your integration platform, a scheduled export.

The rules every integration shares

  • Everything coming in is reviewed before it counts: new, changed, kept and problem rows, accepted or declined by a person. A connector cannot quietly change a model.
  • Rows are matched by type and name, so a connector needs no EA Explorer ids. A delivery never deletes.
  • Every caller signs in with its own identity and only the rights it needs: see Signing in as a system.
  • Secrets never sit in the database: a source's sign-in is the name of a setting (EAX_SOURCE_...).
