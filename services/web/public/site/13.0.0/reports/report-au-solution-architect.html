For: Practising architects

What it shows

What it gathers: SR-06 Interface and integration catalogue, SR-15 Application interaction matrix, SR-22 Impact analysis, VP-02 Application Structure view, VP-05 Layered view, VP-11 Application Cooperation view, VP-13 Implementation and Deployment view, VP-16 Requirements Realization view, VP-52 Security requirements view, VP-57 Agile backlog view, VP-58 Building blocks view, TC-04 Requirements catalogue, DR-01 Dependencies of an entity, DR-02 Dependency matrix between two types, DR-04 Dependency counts and hot spots, GR-03 TOGAF gap matrix.

Why it matters

An audience dashboard gathers, on one page, the headline charts of the reports one kind of person usually needs, so they start from what matters to them instead of browsing the whole catalogue.

In TOGAF terms: Stakeholder management: each audience sees the views that address its concerns. See EA Explorer and the TOGAF Standard.

Who it is for

Solution architect.

How to use it

Use it as the starting dashboard for the Solution architect dashboard: the reports that matter to this audience, together.

How to read it

Each chart is described where it comes from; open the full report from the Reports tab for detail.

Where to find it

Open a model, Reports › Reports, and choose Solution architect dashboard; it opens its dashboard for that model. Every chart can be filtered, and most rows have Open to go to the entity in EA Explorer. The same data is in the model's OData feed for your own tools (OData feeds EA Explorer publishes).
