## Why do this

Installing on a server, setting up backups or a DR site, moving machines: each is a sequence of steps that must be right. The setup guides write every command with your server names and files filled in, for Windows or Linux, so you copy rather than compose. See [[running-the-installation]].

The installation is built to look after itself as far as it can, and to ask before anything risky. These tasks are the decisions it leaves to you: what to run, when, and how far to trust a change.

**In TOGAF terms:** Outside the method: this keeps the tool that holds the Architecture Repository running. See [[ea-explorer-and-togaf]].

**The goal:** A set-up job is done right, with your own values in every command.

> **Before you start** You need the Super Admin or IT Admin role.

## Steps

1. Open **System Admin › Setup** and pick the guide.
2. **Give your values**: the server's name, the files, the folders.
3. Copy each command, or download the whole guide.
