## Why do this

A migration plan, from ADM phase F, orders the work packages into waves and transition states, so change happens in a sequence the organisation can absorb. See [[the-adm]].

A project carries one pass of the ADM from vision to sign-off. Each task here is one of the steps along that route, and the project keeps them together so the whole story can be read later.

**In TOGAF terms:** Phase F, Migration Planning: the implementation and migration plan. See [[ea-explorer-and-togaf]].

**The goal:** The route from today to the target is planned in waves.

> **Before you start** You need a role on the project (Architect or higher), unless a step says otherwise.

## Steps

1. Open the project's deliverables and choose the migration plan.
2. Pick the gap analysis; order the work packages into waves.
3. **Save**; it is the plan's evidence.
