## Why do this

The TOGAF content framework lists the deliverables, artifacts and building blocks architecture work produces. Seeing a project against it shows what is there and what is missing. See [[architecture-repository]].

A project carries one pass of the ADM from vision to sign-off. Each task here is one of the steps along that route, and the project keeps them together so the whole story can be read later.

**In TOGAF terms:** The content framework: deliverables, artifacts and building blocks. See [[ea-explorer-and-togaf]].

**The goal:** You see what a project has produced against the content framework.

## Steps

1. Open the project, **Architecture › Content framework**.
2. Open an area; read what is there and what is missing.
