## Why it matters

The standard reports answer the questions most architecture practices are asked again and again: what we have, what it costs, how it depends on what, and where the risks are. They work on any model built on a metamodel with the matching types and attributes.

**In TOGAF terms:** Architecture views and catalogues that address common stakeholder concerns, in phases B to F. See [[ea-explorer-and-togaf]].

## Who it is for

CIO, CFO, Portfolio manager.

## How to use it

Use it to find overlapping applications to rationalise.

## How to read it

Capabilities with more than one application are candidates; compare the applications' fit, cost and TIME before deciding which to keep.

## Where to find it

Open a model, **Reports › Reports**, and choose **Rationalisation candidates**; it opens its dashboard for that model. Every chart can be filtered, and most rows have **Open** to go to the entity in EA Explorer. The same data is in the model's OData feed for your own tools ([[odata-feeds]]).

For developers and report builders: it reads `rpt.sr25_rationalisation`; its dashboard is `eax-sr25`.
