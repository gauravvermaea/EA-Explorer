## What it shows

**What it gathers:** [[report-sr-01|SR-01 Application portfolio inventory]], [[report-sr-09|SR-09 Application against capability]], [[report-sr-12|SR-12 Application against technology]], [[report-vp-02|VP-02 Application Structure view]], [[report-vp-08|VP-08 Application Usage view]], [[report-vp-09|VP-09 Technology Usage view]], [[report-vp-11|VP-11 Application Cooperation view]], [[report-tm-04|TM-04 Application and organisation matrix]], [[report-dr-02|DR-02 Dependency matrix between two types]], [[report-gr-02|GR-02 Gaps by domain and type]].

## Why it matters

An audience dashboard gathers, on one page, the headline charts of the reports one kind of person usually needs, so they start from what matters to them instead of browsing the whole catalogue.

**In TOGAF terms:** Stakeholder management: each audience sees the views that address its concerns. See [[ea-explorer-and-togaf]].

## Who it is for

Application architect.

## How to use it

Use it as the starting dashboard for the Application architect dashboard: the reports that matter to this audience, together.

## How to read it

Each chart is described where it comes from; open the full report from the Reports tab for detail.

## Where to find it

Open a model, **Reports › Reports**, and choose **Application architect dashboard**; it opens its dashboard for that model. Every chart can be filtered, and most rows have **Open** to go to the entity in EA Explorer. The same data is in the model's OData feed for your own tools ([[odata-feeds]]).
