## Who this is for

People with the **Project Admin** or **Lead Architect** role on a project. Project Admins look after the projects,
templates and libraries of the installation under the **Project Admin** menu.

## A day in your life

You run architecture projects from idea to sign-off. Your day moves between people and progress: setting up a new
project from the right template, getting the charter in front of the sponsor, adding the stakeholders and their key
questions, checking which deliverables are late, chasing a sign-off, logging a decision the board made, and preparing
the project report for the steering committee on Thursday.

## Where EA Explorer fits

EA Explorer holds everything a project needs in one place, laid out the way the TOGAF ADM works: the phases and
steps tailored to this project, the deliverables from the template library, the models it changes, who signs off and
what they decided. Instead of chasing documents across shared drives and email, you see the whole project on one page,
and when it finishes the record stays. See [[the-adm]], [[kinds-of-projects]] and [[projects-and-deliverables]].

## Where you sit in TOGAF

You run the ADM. Each project you set up is one or more passes through its phases, from the Architecture Vision (phase A) to Change Management (phase H), tailored to the project's purpose, with the deliverables, stakeholders and sign-offs the standard describes. See [[ea-explorer-and-togaf]].

## What you have

| Area | Where | What it gives you |
|---|---|---|
| Wizards | Project Admin › Wizards | A new project (blank, from a template, or restored from a backup file) and the jobs on a project |
| Projects | Project Admin › Projects | Every project, its state and its people |
| Templates and libraries | Project Admin › Templates and libraries | Project templates, the project content template library and the project library |
| Principles | Project Admin › Principles | The organisation's architecture principles, as cards |
| Surveys and maturity | Project Admin › Surveys and maturity | Questionnaires to stakeholders, and EA capability maturity assessments |
| The project's page | Open a project | Its ADM wheel and phases, steps, models, deliverables and artifacts, stakeholders, key questions, principles, sign-off, documents, library and reports |

## How it is put together

- **A project** runs one ADM cycle (or a piece of architecture work) with its own people, models, deliverables and
  documents. It starts from one of **14 templates** (for example transformation, as-is documentation, build or buy,
  cloud migration, acquisition) or blank.
- **The TOGAF 10 library** gives the phases, steps and deliverables: 13 phases, 116 steps, 171 deliverables and
  artifacts, and 51 repository folders. You add your own steps and order them.
- **The ADM cycle** is a Full cycle, one of TOGAF's iterations (Architecture Capability, Development, Transition
  Planning, Governance) or your own set of phases. Phases left out are frozen, never deleted.
- **Models in roles**: a project uses models as its baseline, target, transition, scenario, reference or working copy,
  each from a tag of the model it starts from.
- **Documents** live in the project's repository (Mayan EDMS): versions, check-out, acceptance and approval.
- **Sign-off** is by the project's sign-off people, with a quorum; decisions and dispensations go in the governance log.
- **Project roles**: Project Admin, Lead Architect, Architect, Model Admin, Model Sub Admin and Stakeholder.
