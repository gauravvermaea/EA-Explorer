## Who this is for

People who build **reference models** for an industry or a domain (banking, insurance, healthcare...) and the
**metamodels** they use, for others to start their own models from. You need the **Model Creator** role to make models,
and **Library Admin** to publish them in the model library.

## What you have

| Area | Where | What it gives you |
|---|---|---|
| Industry reference models | Model Admin › Model library › External reference models | Banking, Government, Healthcare, Logistics, Manufacturing, Minerals and Mining, Pharmaceuticals, Retail and Telecommunications, and Meridian Assurance (insurance), each with capabilities, value streams, services, processes, products, business objects and a starter landscape |
| Industry packs | A reference model › Pack | Each industry's book, workbook, the metamodel Excel it was built from and its empty template, ArchiMate 4 views, Excel templates and PowerPoints, to download |
| Metamodel workbooks | Model Admin › Wizards, *Model from a metamodel workbook* | A whole metamodel as one Excel workbook: download any model's, change it, make a new model from it |
| The metamodel editor | A model's Metamodel tab | Domains, types, attributes, pick lists, allowed relationships with multiplicity, rules, notation and colours |
| Metamodel drafts | Model Admin › Metamodel drafts | Changes proposed, reviewed and approved before they are published |
| Loading content | A model's Import and export tab | Excel and CSV sheets built for the model's own types, loaded with a preview |
| The model library | Model Admin › Model library | Where a finished reference model is published for everyone to start from |

## How it is put together

- **ArchiMate 4 and the TOGAF 10 content metamodel** are built in, with six EA Explorer extensions for TOGAF business
  architecture (value stream stage, product lifecycle stage, business scenario, control, contract, measure), each marked
  as an extension.
- **A metamodel workbook** has one sheet each for the model's details, domains, pick lists, attributes, types, type
  attributes, relationship types, allowed relationships (with multiplicity) and rules. It is the quickest way to build
  or review a whole metamodel.
- **A reference model** is an ordinary model marked as a reference and published in the library. Others copy it, or
  make a child of it so later changes can be pushed down to theirs.
- **Packs** are files kept with EA Explorer and loaded into Documents at start-up, so every installation has them.
