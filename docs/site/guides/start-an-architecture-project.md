## Why do this

A good start saves a lot later: the right template, the right base models, the right people, the right ADM cycle. See [[kinds-of-projects]] and [[the-adm]].

A project carries one pass of the ADM from vision to sign-off. Each task here is one of the steps along that route, and the project keeps them together so the whole story can be read later.

**In TOGAF terms:** The ADM itself: the phases, steps, deliverables and sign-offs of an architecture project. See [[ea-explorer-and-togaf]].

**The goal:** A project set up right from day one.

> **Before you start** You need the Project Admin role.

## The ways to do it

1. Open **Project Admin › Wizards › New project**: **Blank project**, **From a project template…**, or **Restore a
   project from a backup file**.
2. A template (transformation, as-is documentation, build or buy, cloud migration, acquisition and others) sets the
   phases, steps, deliverables and the models' roles.
3. Choose the **base**: the models the project starts from and the tag each is taken at.
4. Give people their roles on the project's **People** tab: Project Admin, Lead Architect, Architect, Model Admin,
   Model Sub Admin or Stakeholder.

## Check it worked

The project opens on its ADM wheel; Architecture Work › My projects lists it for everyone on it.
