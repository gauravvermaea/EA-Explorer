# EA Explorer 5.5.0: Release 5.5, enterprise discovery

Release 5.5 (16 Nov 2026; the owner: "Build this release"): **enterprise discovery**, run by the people's own AI through
MCP; **architecture decision records and dispensations** in the Governance Log; and the **Live browser full screen**.

**Before updating:** take a backup (`.\eax backup before-5.5.0`). From 5.1.0 the update runs migrations 0093 to 0097
(decision records and dispensations, enterprise discovery, the version, the MCP suite, two indexes: tables, columns, two roles, rows, constraints and indexes). A **clean
rebuild** is needed: the API, the MCP server, the job runner, Keycloak's realm (two new roles) and the screens change
(`.\eax clean-restart`). Then `.\eax test full`.

## Enterprise discovery (R5.5)

The owner's design leads: "EA explorer will only be source and sink of information. Let MCP and LLm run this one".
EA Explorer keeps the setup and takes back what is found; it never signs in to a source at run time, never reads or
transcribes anything, holds no AI key and runs nothing on a timer.

- **Discovery projects** (AI (MCP) › Enterprise discovery): a name, the **target model** the AI commits into (a child of
  the main model to review first, or the main model once you trust the AI), the defaults of a run, and a schedule.
- **A new global role, Discovery Admin** (`eax-discovery-admin`): sets up discovery projects and their sources for any
  model; Super Admins can too. Everyone who may read a project's target model sees it and its runs.
- **Sources of every kind**: mailboxes, document folders and shares, FTP, SFTP, SharePoint, Git repositories, wikis,
  ticket systems and the CMDB, Teams and Slack channels, database schemas (read only), cloud storage, cloud accounts and
  recordings. Each says where it is, what to include and whether attachments are read.
- **Test, then forget**: a Discovery Admin types a source's sign-in (a key or token, a user name and password, a client
  certificate, or single sign-on) to **Test the link**; it is used once and forgotten. Only the method and the result
  are kept. At run time the AI brings its own access.
- **The AI runs it through MCP** with its own sign-in: `run discovery project <name>` asks whether to read only what is
  new or everything, and whether to mark or delete what is gone (the project's defaults suggested). The target model is
  **tagged before and after** every run, so comparing the two tags shows what the run changed, the metamodel first.
- **Found in**: every element and relationship the AI adds or changes keeps where it was found (the source, the item,
  where in it, a link). An element's new **Found in** tab shows it.
- **"AI agent on behalf of"** the person who set the project up: the run's commit, its tags and its Found in say so.
- **May be the same as**: where the AI is unsure an element is new, it adds it and flags the one it may duplicate; merge
  them with Dedupe, then mark the flag Dealt with.
- **NOT FOR AI USE OR AUTOMATED PROCESSING** is respected: such items are never read; their title, place and date are
  listed in the run's report as skipped.
- **Decision records and dispensations found in the sources** are logged by the AI as Drafts in the organisation's
  Governance Log, with where they were found; the Architecture Board accepts or rejects them.
- **The schedule is a marker**: the AI client's own scheduled task asks `discovery projects due` and runs each. A run
  more than two hours late shows as **Overdue** on the project and raises an alert (System Admin › Alerts).
- Eight MCP tools: `discovery_projects`, `discovery_projects_due`, `run_discovery_project`, `discovery_record_found`,
  `discovery_report_skipped`, `discovery_log_decision`, `discovery_finish_run`, `discovery_run_report`.
- The sample data adds a discovery project on the demo estate with five sources (example addresses; no sign-in kept).

## Architecture decision records and dispensations (R5.5.1)

- **ADRs and dispensations, first-class**: numbered per year across the organisation (ADR-2026-001, DISP-2026-001),
  each with its template (an ADR's context, options, decision, rationale and consequences; a dispensation's waived
  standard, systems, justification, risks and remediation), its ADM phase, record type or sponsor, and a lifecycle.
- **The organisation's own Governance Log** (Repository › Governance Log): the new **Architecture Board** role
  (`eax-architecture-board`) logs, accepts and rejects records outside any project; in a project, its sign-off people do.
- **Links both ways**: to elements, requirements, principles, standards and other records; a newer ADR that supersedes
  an older one marks it Superseded. An element's **Linked decisions and dispensations** tab shows them.
- **Dispensations end**: every dispensation has an expiry date; its owner, sponsor and the Board are told before it ends
  (30 days, a setting) and on the day, when it becomes Expired.
- **The governance report**: decisions by status and project, active dispensations by expiry date, on screen and as an
  OData feed for BI tools (`/api/v1/odata/governance/`).

## Self-test

- **An MCP suite** (`.\eax test mcp`; Self-test › MCP; part of the full test): the MCP server called over HTTP exactly as
  an AI client calls it, no language model. Every tool listed; every tool that reads called with the run's own data and
  never a server error; a change kept as the person's own; refused without a token, with a read-only token and without
  the role; every call in the AI activity log (R5.5.5).
- **Enterprise discovery and decision records in the API suite**: a discovery project, its sources and Test the link
  through REST, then a whole run through MCP as an AI makes it (the reading assumed), and the decision records and
  dispensations through REST, 28 checks (R5.5.4).
- **The Live browser full screen** (R5.5.2): Self-test › Watch › Full screen fills the screen with the test's browser; a
  thin bar shows the step with Pause, Continue and Step, and hides after three seconds (Esc leaves).
- The page sweep opens the Governance Log and Enterprise discovery.

## Also in this release

- **Template setup › Templates: View and Download** for every template that has its file. View shows it here without
  downloading: a PDF or a picture as it is; Word's headings and paragraphs, PowerPoint's slides, Excel's sheets and first
  rows as text (R5.5.6).
- **Setting up a discovery project** offers only live working models as its target (no library models or root
  metamodels, nothing frozen, archived or read only; the API refuses them too), with a **New model** button that makes
  one and picks it (R5.5.7).

## Fixed while testing it

- A discovery project deleted and set up again could not run: its first run's tags clashed with the earlier ones.
- A discovery run that found nothing new could not finish.
- With the drawn views' service down, two MCP tools failed with a server error instead of saying so.
- Two foreign keys of the discovery tables had no index (the self-test's database check): added (migration 0097).
- "A architecture decision record needs..." now reads "An architecture decision record needs...".
