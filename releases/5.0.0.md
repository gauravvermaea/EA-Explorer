# EA Explorer 5.0.0: Release 5

Release 5 (built 15 Nov 2026, being tested; D696: built whole, tested with the automation, its bugs fixed, then
released, nothing carried forward): running EA Explorer on a server with confidence: security at the front door,
alerts, logs, database maintenance, an optimisation report, a service desk, and testing that runs by itself.

**Before updating:** take a backup (`.\eax backup before-5.0.0`). From 4.0.0 the update runs migrations 0078 to 0086
(machine credentials' addresses, the Auditor role, alerts, database maintenance runs, the service desk, the
optimisation reports, the performance suite, sizing estimates, the live browser; tables only). A **clean rebuild** is
needed: the operations helper, the front door's configuration, the set-up and the test runner change
(`.\eax clean-restart`). Then `.\eax test full`.

## Security

- **IP allow lists** at the front door, per place (the screens, sign-in, administration, MCP, machine access), never
  locking out the person who sets them; a machine credential limited to its own addresses (R5.2, D686; `eax allow`).
- **Multi-factor sign-in** as a setting, off by default: for admins or everyone (R5.3, D690).
- **The Auditor role** (eax-audit): sees everything a Super Admin sees, changes nothing, never sees a secret (R5.22, D693).
- **Signed deployments**, for an organisation that wants them: `eax sign` and `eax verify`; an update refuses a version
  not signed by a trusted key once one is trusted (R5.10, D685).
- **Automated security testing**: weekly by itself and nightly in CI; a signed-in ZAP scan; code, secrets and licence
  scanning; the attacks of Release 3 kept as tests; a gate on high and critical findings with accepted ones that expire;
  the trend on Self-test › Security and an alert on a new finding (R5.17, D698).

## Operations

- **Alerts**: checks with levels, hold, flapping, acknowledge, silence, escalation, email and webhooks (R5.9, D689).
- **Logs**: levels, every container's logs kept and rolled, the web log of every call, on System Admin › Logs (R5.6 to
  R5.8, D688).
- **Database maintenance**: every database checked daily, tidied nightly without locks, compacting and lock resolution
  after a preview (R5.12, D691; `eax db`).
- **The optimisation report**: monthly suggestions with their evidence and the people who made and look after each
  model or project, applied only with a yes, for a whole model or project; on screen and as Excel (R5.1, D697;
  `eax optimise`).
- **Server sizing**: a best estimate of RAM, CPU and disk, per container too, with a compose override (R5.19;
  `eax estimate`).
- **Where the data lives**: one base folder, a folder per kind of data (R5.4, D687; `eax folders`).
- **The service desk**: ask for things from a catalogue; each team's queue (R5.11, D692; `eax ticket`).
- **The version review** every three months, as a scheduled task (R5.21, D694).

## Testing

- **Performance testing**: `eax test performance`, k6 with many people at once, compared with the last release's
  baseline; part of the full test (R5.18, D695).
- **Watch the tests' browsers live**, streamed only while watched; slow motion and pause after each step; every
  journey's video and trace kept for a watched run (R5.20; `eax test watch --browser`).

## For developers

- **Every module, class and function documented**, kept so by a test; `docs/functional-description.md` (R5.14, R5.15).
- **docs/handover.md** and `eax dev check` for whoever takes the work over (R5.16).
