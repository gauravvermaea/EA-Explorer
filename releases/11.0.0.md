# EA Explorer 11.0.0: Release 11, certificate mode working and tested

Release 11 (built 22 Nov 2026; **accepted 22 Nov 2026**, the owner: "R11 accepted"): the services can now sign in to
the database with **certificates** EA Explorer makes for each of them, instead of passwords, and this works end to end:
on a clean install, after a clean restart, and in the tests. You can check it with one command and switch between the
two modes from the screen.

**Before updating:** take a backup (`.\eax backup before-11.0.0`). The update runs migration 0116. The API, library,
views, test runner, operations and web images change, so run `.\eax clean-restart`, then `.\eax test smoke`.

## For system administrators

- **Certificate mode works.** Each service (the API, library, drawn views, Keycloak, Reports, Documents and the
  database) can read its own key and no other. Before this release the API could not read its key, so certificate
  mode stopped at start-up.
- **`eax certs check`**: says, for each service, whether it can read its key; it fails if any cannot.
- **Switch from the screen**: System Admin › Secrets has **Switch to certificates** or **Switch to passwords**. It runs
  `eax certs switch`, then offers the restart; nothing changes until EA Explorer restarts.
- **The choice is remembered**: `eax certs switch` now keeps the mode for the next clean restart (before, a clean
  restart went back to the old mode).
- **Choose the mode at a clean restart**: `eax clean-restart` and `eax clean-run` take `--certificate` or
  `--password`.
- **The Secrets page shows what applies**: the part for the mode you are in comes first. In password mode the
  certificates are one line saying they are not used. In certificate mode the services' own database logins are marked
  *not used*; their passwords are kept, and still rotated, so a switch back works at once.

## Testing

- **The smoke and full tests can run in certificate mode**: the test runner now has the API's certificate folder (read
  only) and can read its key.
- New unit tests check that every Dockerfile gives its service the right group for its key, and that the Secrets page
  marks exactly the logins the database signs in by certificate.

## Known issues

- `eax diag` writes an empty report (R14.23, Release 14).
- Four Jenkins pipelines (eax-admin's start and maintenance page on, off and clear) can never run (R14.18, Release 14).
- The guides and How do I pages do not describe certificate mode yet: they are written with every other guide in
  Release 16.

## In one paragraph (for the GitHub release)

EA Explorer 11.0.0 makes certificate mode work end to end: the services sign in to the database with certificates EA
Explorer makes for each of them, each service reads only its own key, and `eax certs check` confirms it. You can switch
between passwords and certificates from System Admin › Secrets, the choice is kept across clean restarts, and
`eax clean-restart` takes `--certificate` or `--password`. The Secrets page now shows what applies to the mode you are
in. Take a backup, then `.\eax clean-restart`.
