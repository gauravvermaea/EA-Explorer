# EA Explorer 4.0.0: Release 4

Release 4 (accepted 15 Nov 2026): Reports on Superset 6.1.0 and tested as people use them, an AI (MCP) menu of its
own with tools to run the installation, project steps in your own order, and the bugs of the last two full tests.

**Before updating:** take a backup (`.\eax backup before-4.0.0`). From 3.5.0 the update runs migrations 0075 to 0077
(the self-test's reports suite, a step's history may say it was moved, and the version; nothing removed). The reports
image is new (Superset 6.1.0): `.\eax update` rebuilds it; the report dashboards are imported again at its first start
(a few minutes). After it, run `.\eax test smoke`.

**Known issue, for Release 5.6:** in the full self-test, "backup: an infrastructure backup" can end with
"RemoteDisconnected" after about six minutes (the backup itself is checked by the backup and restore suites).

## Reports

- **Apache Superset 6.1.0** (from 4.1.2), with every report chart and setting checked against it (R4.7, D680).
- **Report links open their report**: clicking a report from a model lands on that dashboard, signed in once through
  Keycloak, also when already signed in to Reports.
- **The report dashboards are imported at every start of Reports** (its container now sees them), each said in its log.
- **A self-test suite for Reports** (`eax test reports`, and in the full test): Keycloak test users sign in as people
  do; every dashboard opens with every chart answering, as the Super Admin and the Report Viewer; each person sees
  only their own models and only committed content; the IT Admin sees none; the files reports make open (R4.1, D681).

## AI (MCP)

- **AI (MCP) is a menu of its own, for everyone**: Connect, What it can do, My AI activity and, for admins,
  Everyone's AI activity (R4.20).
- **Tools to run the installation** for Super Admins and IT Admins: its state, the resource history, what is slowing
  things down (in words, worst first), container logs, backups and unused models and projects; and, each previewed
  and then confirmed, take a backup, restore one, change the number of API and job servers, archive a model or a
  project. Never while the self-test or a restore runs; nothing deleted (R4.22, D683).

## Projects

- **The ADM steps in your own order**: move a step up or down in its phase (▲▼), say where a new step goes, and set the
  order in the project wizard; the step's history says it was moved (R4.21).

## Command line and documentation

- **docs/starting.md**: the first start and every start after, step by step, on a laptop and a server.
- **`eax`'s screen** no longer quits to the command prompt after each command (R4.11).

## Fixed

- A body that is not JSON sent to a model's archive was acted on; three server errors where "not found" belongs;
  System Admin › Scaling failed when a container had just gone (R4.13 to R4.15).
- The self-test's own mistakes (long answers cut, values not quoted, the iteration journey's step 14) (R4.16, R4.17).
- The Superset image's critical findings: Pillow 13 and a newer uv (R4.24).
- Documents on the Health page says it is answering instead of "HTTP 302".

## Not in this release

The key vault (OpenBao) was built and then switched off by the owner: it is Release 7, discussed before it is
brought in. Moved to Release 5: the code documentation and handover (R4.3 to R4.5), automated security and
performance testing (R4.8, R4.9), server sizing (R4.10), watching the screen tests live (R4.12), the three-monthly
version review (R4.23); the backup issue above is Release 5.6.
