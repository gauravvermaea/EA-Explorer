# EA Explorer 3.5.0: Release 3.5

Release 3.5 (14 Nov 2026): memory. How much each container needs is measured, in one go or all the time, and the
laptop needs less: two containers fewer and Documents and Keycloak sized for where they run.

**Before updating:** take a backup (`.\eax backup before-3.5.0`). From 3.0.0 the update runs migrations 0073 and 0074
(the resource history's table, and the version; nothing removed). The `operations` and `personal` containers are gone:
`.\eax update` and `.\eax clean-restart` remove them (by hand: `docker compose down --remove-orphans`). After it, run
`.\eax test smoke`.

**Known issues, fixed in Release 4** (R4.13 to R4.17, as in 3.0.0): a body that is not JSON sent to a model's archive
is acted on; three server errors where "not found" belongs; System Admin › Scaling fails when a container has just gone;
the iteration journey's step 14; and some of the self-test's own checks.

## The resource history

- **Memory, CPU, disk and the database's cache, recorded all the time**: every 15 minutes, while people work and while
  the self-test runs, each container's memory, CPU, network and disk, the Docker host's memory left and swap, the file
  systems and the database's cache hit rate, size and connections are kept, each sample marked with what was happening
  (a self-test, a backup, a restore, a start-up) (R3.5-M8, D679).
- **On System Admin › Footprint**: charts over 6 hours to 90 days or a period of your own, the busy stretches shaded; each
  container's average and peak; CSV; the interval (off, 1 to 60 minutes) and how long it is kept (every sample 7 days,
  then one an hour; 90 days in all); a shorter interval for a test that goes back by itself. A Super Admin deletes a
  period, everything before a date or all of it (audited). `eax footprint --history [days]` on the command line.

## Measuring memory

- **`eax footprint --watch [minutes] [label]`**: every container's memory every 15 seconds, its lowest, average and
  peak, the whole installation's peak beside the guide (10 GB on a laptop, EAX_MEMORY_TARGET_MB; a guide, not a limit)
  and whether the Docker host paged. Every self-test run is watched the same way (memory.md in its folder).
- **`eax measure`**: restart (if asked), start-up, a snapshot, the smoke test, at rest, in use and the full test, each
  checked, carried on with `--from N`, ending in one summary (work/footprint/measure-*.md). `--no-full` leaves the full
  test out; on a server it is safe by default (no clean restart, no full test unless asked) (R3.5-M1).

## Less memory on a laptop

- **One API again**: the operations and personal data services are served by the API container (D677): about 0.35 GB.
  Their data keeps its own schemas and connection strings, and a part can run in a container of its own again by
  configuration only (EAX_SERVE and EAX_OPERATIONS_INTERNAL_URL or EAX_PERSONAL_INTERNAL_URL) (R3.5-M1b).
- **Documents (Mayan)**: its workers were one process per processor core; now EAX_MAYAN_WORKER_CONCURRENCY (laptop 1,
  server 2) and EAX_MAYAN_WEB_WORKERS (laptop 2, server 3): about 1.5 GB on a laptop. Large OCR jobs take longer.
- **Keycloak**: its Java heap by EAX_KEYCLOAK_HEAP (laptop -Xms64m -Xmx512m, server -Xms256m -Xmx1024m): about 0.2 GB.

## Fixed

- A self-test run was sometimes "not measured": its memory watch now finishes before the run ends.
- System Admin › Footprint broke (and the screen tests after it) when `eax measure`'s progress file was in its folder.
- `eax measure`'s summary, carried on with `--from`, listed every earlier attempt and called start-up paging a problem.
