# EA Explorer 14.5.0: Release 14.5, the full tests made to pass

Release 14.5 (built 25 to 27 Nov 2026; **accepted 27 Nov 2026**, the owner: "ok lets accept this release"): every bug
the full tests of 25 to 27 Nov found fixed, code coverage over 85%, and a DR drill that restores whatever is still
starting. The DR drill passed after the fixes: **10 minutes** from shutting the installation down to the DR copy
restored and signed in to, every model, element, relationship, project, document and person counted the same.

**Before updating:** take a backup (`.\eax backup before-14.5.0`). The update runs migrations 0124 (the dependencies
report reads the element's domain) and 0125 (the version only). The api, web, ops, backup and test runner images
change: `.\eax down` then `.\eax up` is enough (no data is changed), then `.\eax test smoke`. Reports imports every
dashboard once more at its first start (a few minutes; later starts import only what changed). Refresh the browser
(Ctrl+F5).

## What the tests showed

- **Self-test** (full test of 26 Nov, after a clean restart): 3,629 checks passed, 3 failed, all three fixed: the
  security gate (a Debian fix a cached build missed, D951), and DR-01 and a stall (both a browser frozen by the
  dependency matrix, D954).
- **Code coverage:** the API 87.3%, the screens 93.4%, the jobs 85.9% (the bar is 85%).
- **Backup and restore:** passed, nothing lost.
- **DR drill** (27 Nov): passed, 10 minutes to recover.
- **Dev check, SonarQube:** passed.

## For everyone

- **A project page opens at once**: it read every element and relationship of the repository to find its goals'
  outcomes, 20 seconds and more each time (D949).
- **The project report's CSV downloads** (it failed with "s.map is not a function", D950).
- **The dependency matrix (DR-02) opens with one row type and one column type**, changed in its filters; with none
  chosen, an administrator's browser froze drawing every element against every other (D954).
- **The dependencies report (DR-01) works again**: it reads the element's domain (ArchiMate 4) (D939, D946).
- **The API answers several requests at once**: a page's calls no longer queue behind a slow one (D943).

## For system administrators

- **A restore swaps its databases in with no new session allowed**: a service still starting (Reports, in a DR
  copy) could connect between closing the sessions and the rename, and the restore failed and was undone (D952).
- **A clean rebuild builds without Docker's cache**, so every Debian fix released since comes in (D951).
- **Reports keeps its datasets as the code says**: importing a dashboard now overwrites its datasets too (D946).
- **The Logs page's file list is quick**: each closed log file's size is read once (D948).
- **`eax console`** has *Test this installation*: the smoke test, the full test, the full test with the risky suite
  and what failed again; its command prompt names them (D953).

## Testing

- **A stall watchdog**: 15 minutes with no check or log line records "stalled at <step>" and closes the test
  browsers so the run goes on; 15 more end the run cleanly (D942).
- **Stop is seen at the next check**, not only at the next log line (D945).
- **A rerun of failed checks opens only the report dashboards it repeats**: minutes, not 90 (D944).
- **A failed browser step says what the database was busy with** (D947).

## Known issues

- **The full test on a laptop with little memory** can run out of memory near its end (the last attack scan,
  Gitleaks over the git history): give Docker more memory, or run it overnight with nothing else open.
- **Before Release 22**, do not run `clean-restart`, `clean-run` or `cleanup --all` on a server: they delete every
  database without asking. Use `.\eax up` or `.\eax restart`.
